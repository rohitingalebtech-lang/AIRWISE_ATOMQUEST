🛡️ Safety & Physical Limitations Notice (Feature 8)

Mandatory operational context for judges and evaluation committee.

Software Prototype Only
❌ No Physical Fan Connection

AirWise is strictly a software-only simulation for Round 2. Calculated fan speeds (Levels 1 to 5) are algorithmic recommendations, not electronic PWM signals or electrical motor commands. No physical fan is energized.

❌ No Live Hardware Sensors

All environmental inputs (temperature, humidity, time of day) are simulated via software controls. No physical DHT11, DHT22, BME280, or thermistor sensors are connected or polled in this prototype.

❌ Hardware Fail-Safe Not Validated

Electrical isolation, thermal runaway cutoffs, stall current detection, and optical relay decoupling have not yet been implemented or tested on physical motor hardware. Dangerous direct actuator connections have been purposefully excluded.

✔️ Safe Academic Demonstration

The prototype proves software logic: machine learning inference, statistical model evaluation, persistent feedback logging, and instance-based personalization without physical electrical risk.

🚀 Physical Implementation Roadmap (Round 3)

Planned hardware integration pathway for advancing beyond software prototype.

Future Scope
01

Microcontroller & Sensor Interface

Integrate an ESP32 microcontroller with a calibrated I2C SHT31 sensor for ±0.2°C ambient temperature and ±2% RH readings.

02

BLDC Motor & Opto-Isolated PWM Driver

Deploy a 4-wire BLDC ceiling/table fan motor with tachometer feedback and optocoupler isolation for electrical safety.

03

Hardware Watchdog & Thermal Fail-Safe

Implement an independent thermal bi-metal fuse and hardware watchdog timer to guarantee automatic fan shutoff if communications freeze.

04

Edge TinyML Deployment

Quantize the Decision Tree into C code / TensorFlow Lite for Microcontrollers to run inference natively on the ESP32 without requiring a PC.
